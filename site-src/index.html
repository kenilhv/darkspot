Prototype · disaster-response decision support

DarkSpot

Every disaster dashboard ranks the places that are reporting. The places most at risk are often the ones that have gone completely silent — because their connectivity was marginal before the disaster and gone after it. DarkSpot ranks the silence.

It collects reports from places with no network at all (phone-to-phone mesh relay, store-and-forward), corroborates them by distinct device identity, and hands the result to whoever actually holds authority on the ground. It never issues an instruction.

What this is, honestly. A working prototype, not a deployed system. The data below is real — 1,440 administrative units from the UN's Humanitarian Data Exchange, flood extent from Copernicus/HOT, computed live in ClickHouse — but no DarkSpot device has ever been deployed in the field, so silence here means absence of data, not a settlement going quiet. Every UAV route shown is a labelled simulation, never deconflicted with any airspace authority. Before a single real decision could lean on this it needs an authorised partner organisation, airspace integration, and field validation.

The four surfaces

  • live data

    Coordinator view

    61 in-scope settlements for the Trishuli basin flood, ranked by silence × population × hazard. Every card prints its own factors, its confidence tier, and what the data cannot say. The rank is a sort order, never a risk score.

    React · @darkspot/ui · WCAG-checked palette

  • simulation

    Swarm-intelligence layer

    Mesh formation by particle-swarm relay placement, AntHocNet-inspired adaptive routing against an AODV baseline, and taskforce allocation two ways — Hungarian where a unit can reach command, decentralised auction where it can't. Press Run and watch the mesh form.

    Every algorithm cited to its paper on the page itself

  • live model

    Grounded chat LibreChat

    A coordinator asks in plain language; the answer comes back as cited rows from ClickHouse, never as a command. A deterministic guard sits between the model and the user and blocks any imperative before it is ever shown — enforced in a proxy, not hoped for in a prompt.

    Local stack · localhost:3080 · ask about Trishuli

  • live data

    ClickHouse + Postgres OLAP + OLTP

    Postgres holds canonical state and every human decision. ClickHouse reads it live over a cross-database bridge and recomputes the silence ranking on each query — the elapsed clock advances between two runs of the same query, because nothing is precomputed.

    darkspot.priority_rank · darkspot.silence_duration

Four rules the build is not allowed to break

  1. No dispatch action exists in the data model. DarkSpot can say what is known. It cannot say where to go.
  2. No casualty, location or urgency field becomes actionable without a named human. Enforced as a NOT NULL column, not a UI convention.
  3. The safety-critical core runs with no LLM at all. Ranking and allocation are deterministic; the model only narrates a result that already exists.
  4. Every UAV route is a labelled simulation until deconflicted with a real airspace authority. Uncoordinated drones ground real rescue aircraft.

Built for the ClickHouse Better Days hackathon, and continuing past it. Motivated by the Trishuli basin glacial-lake outburst flood of 26 August 2026, but built to be region- and hazard-agnostic: administrative boundaries, population and hazard extent are pluggable connectors, and the system stays inert for a region until a real organisation registers for it.
